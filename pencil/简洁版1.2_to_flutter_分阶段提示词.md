# 简洁版 1.2 -> Flutter 分阶段迁移提示词

这份文档的目标，是让后续 AI 在读取 `z/简洁版1.2.pen` 后，按小步迭代方式把页面迁移到 Flutter 项目里，而不是一次性改完整个应用。

使用方式：

1. 先把“通用总提示词”发给 AI。
2. 然后一次只发一个“阶段提示词”。
3. 每完成一个阶段，都先验收，再进入下一阶段。
4. 如果某个阶段结果不稳定，就继续在该阶段内修正，不要跳到后续阶段。

---

## 一、这套页面在 Pencil 中的拆分

当前 `z/简洁版1.2.pen` 已经天然分成 8 个适合迁移的页面：

- `1.1 Open A New Session`
- `1.2 processing`
- `1.3 Aggregated Draft`
- `1.4 Final Summary Chat`
- `3. Knowledge Base Home`
- `3.1 Knowledge Base Session`
- `3.2 Knowledge Base Chat`
- `3.3 Knowledge Base Sources`

建议迁移顺序：

1. 基础工程与设计令牌
2. 视频总结入口页
3. 视频处理中页
4. 聚合草稿页
5. 最终总结聊天页
6. 知识库首页
7. 知识库会话页
8. 知识库聊天页
9. 知识库来源页

也就是说，先做“视频总结”整条链路，再做“知识库”。

## 二、通用总提示词

把下面这段先发给 AI，作为整个迁移任务的总约束。

```text
你现在要把一个 Pencil 设计稿迁移到 Flutter 项目中，但必须按阶段推进，不能一次性完成全部功能。

请严格遵守以下规则：

1. 先阅读并理解 pencil/简洁版1.2.pen，对照其中的页面结构、层级、间距、圆角、配色、卡片关系、底部导航、输入区和信息密度进行实现。
2. 每次只完成我当前发给你的那个阶段，不要顺手实现下一个阶段，不要提前补全整个应用。
3. 优先保证界面结构、视觉层级、页面跳转和组件边界正确；在早期阶段可以使用假数据，不要急着接真实接口。
4. 如果项目中已有状态管理、路由、主题、目录结构，请优先复用现有方案；不要无故引入大型新依赖。
5. 如果项目中没有对应基础设施，只允许做当前阶段所需的最小增量。
6. 所有改动都必须可运行，且范围可控。避免大规模重构、避免改动与当前阶段无关的页面。
7. 保持简洁版 1.2 的视觉风格，不要自行改成另一套审美：
   - 整体为浅色、克制、轻蓝灰渐变点缀
   - 卡片圆角偏大
   - 边框较浅，阴影轻
   - 留白充足，信息块分区明确
   - 重点操作使用蓝色主按钮
8. 优先提炼可复用的小组件，但只抽取当前阶段已经重复出现的部分，不要过度设计。
9. 如果发现 Pencil 中某些细节不适合 Flutter 原样实现，请做“视觉等价实现”，并在结果说明中明确指出。
10. 完成后只输出以下内容：
   - 本阶段做了什么
   - 改了哪些文件
   - 还有哪些刻意没做
   - 我现在应该如何验收

技术执行要求：

- 先实现静态 UI 和交互骨架，再补状态。
- 默认先用本地 mock 数据。
- 不要接入网络请求，除非我当前阶段明确要求。
- 不要补齐登录、支付、埋点、国际化、测试框架等与当前阶段无关内容。
- 路由只增加当前阶段需要进入的页面。
- 如果当前阶段包含列表或卡片，先确保滚动、间距和适配正确。
- Flutter 代码要可维护，拆分适度，不要把整个页面都塞进一个超长 build 方法。

停止条件：

- 当前阶段完成后，立即停止，不要继续做下一阶段。
- 如果你认为下一阶段需要开始，请先告诉我，不要直接实现。
```

## 三、阶段 0：基础工程与设计令牌

这个阶段不做业务页面，只做迁移地基，避免后续每一阶段都反复调整样式。

### 这一阶段的目标

- 建立与简洁版 1.2 相匹配的 Flutter 基础主题
- 明确页面容器、卡片、按钮、输入框、底部导航的基础样式
- 建立最小路由壳子，先预留视频总结和知识库两个入口

### 这一阶段不要做的事

- 不实现完整视频总结流程
- 不实现知识库具体页面
- 不接接口
- 不做复杂状态管理

### 可直接发给 AI 的提示词

```text
基于 pencil/简洁版1.2.pen，先只做 Flutter 迁移的“阶段 0：基础工程与设计令牌”。

这次只允许你完成下面这些内容：

1. 梳理并落地一套最小可用的视觉基础：
   - 页面背景色
   - 主文本色 / 次文本色
   - 主蓝色强调色
   - 浅蓝灰渐变或等价高亮背景
   - 边框色
   - 大圆角卡片样式
   - 轻阴影样式
2. 抽出当前后续页面肯定会复用的基础组件或样式封装：
   - 基础页面容器
   - 基础卡片容器
   - 主按钮
   - 次级按钮或轻量胶囊按钮
   - 输入区容器样式
   - 底部导航容器样式
3. 建立最小路由骨架，只需要：
   - 首页占位
   - 视频总结模块入口占位
   - 知识库模块入口占位
4. 如果项目中已有 Theme、Router、目录结构，则在现有基础上最小增量接入；如果没有，再补最少需要的实现。

严格禁止：

- 不要实现具体业务页面内容
- 不要做视频上传、处理逻辑、聊天逻辑
- 不要提前创建一堆未来可能用不到的抽象层
- 不要引入与当前阶段无关的新依赖

完成标准：

- 可以运行
- 能看到基础壳子和占位入口
- 视觉基调已经接近 Pencil 稿
- 代码结构足以支撑后续分阶段继续加页面

输出时请说明：

- 你新增或修改了哪些基础样式、组件、路由
- 哪些后续页面还没有开始做
- 我应该从哪里启动和验收
```

## 四、阶段 1：视频总结入口页

严格禁止：

完成标准：

- 页面视觉基本还原
